# 월계ON-AI

> 사진 한 장으로 시작하는 우리 동네 소상공인 홍보와 골목상권 탐방 서비스

## 프로젝트 소개

**월계ON-AI**는 서울 노원구 월계1동의 소상공인과 주민을 연결하는 지역 상권 활성화 서비스입니다.

소상공인은 홍보 문구, 카드뉴스, SNS 운영에 필요한 시간과 전문 인력이 부족하고, 주민은 가까운 가게의 신메뉴와 할인 정보를 제때 발견하기 어렵습니다. 월계ON-AI는 이 정보 격차를 AI 홍보 자동화와 라이브 동네 지도로 줄이고, 방문 퀘스트를 통해 실제 골목상권 방문으로 이어지게 합니다.

## 해결하려는 문제

- 소상공인의 온라인 노출과 디지털 홍보 역량 부족
- 신메뉴, 할인, 재고 소진 등 동네 가게의 실시간 정보 전달 부족
- 익숙한 프랜차이즈와 대형 매장에 집중되는 소비
- 고령 주민과 이동약자가 이용하기 어려운 디지털 서비스

## 핵심 기능

### 1. AI 홍보물 생성

가게 사장님이 제품 사진 한 장과 간단한 키워드 또는 음성을 입력하면 AI가 홍보 콘텐츠를 생성합니다.

- 주민 친화형, 트렌디형, 가성비형 문구 생성
- 카드뉴스 및 숏폼 홍보 소재 생성
- 월계1동 대학생, 주말 가족 등 지역 특성에 맞는 키워드 추천
- 생성된 홍보 문구의 TTS 음성 변환

### 2. 라이브 동네 지도

주민은 별도 앱 설치나 로그인 없이 웹에서 동네 가게와 실시간 소식을 확인할 수 있습니다.

- 지도 위 매장별 홍보 콘텐츠 및 이벤트 표시
- 오늘의 신상품·할인 피드
- 매장 정보, 메뉴, 운영시간 확인
- 가게의 턱 유무, 엘리베이터 등 배리어프리 정보 제공

### 3. GPS 기반 상권 탐방 퀘스트

지도에 표시된 매장을 직접 방문하고 퀘스트를 완료하면 마일리지와 리워드를 받을 수 있습니다.

- GPS 기반 방문 인증
- 여러 매장을 순회하는 테마별 탐방 코스
- 방문 스탬프 및 마일리지 적립
- 쿠폰 또는 지역 상권 혜택으로 연결되는 리워드

### 4. 접근성을 고려한 서비스 설계

월계1동의 다양한 연령대 주민이 함께 사용할 수 있도록 정보 접근성을 우선합니다.

- 큰 글씨와 큰 버튼 중심의 간편한 UI
- 음성으로 들을 수 있는 홍보 콘텐츠
- 매장별 접근성 정보 태그
- 주민 누구나 이해하기 쉬운 지도와 정보 구조

## 지역 데이터 기반 문제 정의

월계1동은 20대와 60대 이상 주민이 주요 유동인구 축을 이루며, 매출은 주말과 17~21시에 집중되는 특성이 있습니다. 이러한 지역 특성 때문에 학생층의 소비를 골목 안쪽 매장으로 확산하고, 고령 주민도 쉽게 접근할 수 있는 정보 제공 방식이 필요합니다.

회의에서 정리한 주요 근거는 다음과 같습니다.

- 월계1동 총인구: 20,133명
- 60세 이상 인구: 6,090명
- 20~29세 인구: 3,654명
- 유동인구가 가장 높은 시간대: 17~21시
- 주중보다 높은 매출이 나타나는 요일: 토요일

## 서비스 이용 흐름

```text
사장님: 사진·키워드 입력
				↓
			AI 홍보 문구·이미지·음성 생성
				↓
			라이브 동네 지도와 오늘의 피드에 게시
				↓
주민: 가게 발견 → 퀘스트 참여 → GPS 방문 인증
				↓
			마일리지·쿠폰 획득 및 골목상권 재방문
```

## 기대 효과

- 소상공인의 홍보 제작 부담과 온라인 진입장벽 완화
- 주민의 동네 가게 발견 및 이용 기회 확대
- 방문 퀘스트를 통한 골목상권 내 소비 순환
- 고령 주민과 이동약자를 포함하는 지역 정보 접근성 향상
- 대학생과 지역 주민이 함께 만드는 지속 가능한 상권 데이터

## 개발 예정 기술

빠르게 MVP를 만들고 실제 사용자 흐름을 검증할 수 있도록 다음 조합을 권장합니다.

- Frontend: Next.js, TypeScript, Tailwind CSS
- Backend 및 Database: Supabase (PostgreSQL, Auth, Storage, Realtime)
- AI 홍보물: OpenAI API 또는 Gemini API
- 음성 변환: Google Cloud TTS 또는 네이버 클로바 보이스
- 지도 및 위치: 카카오맵 API 또는 네이버 지도 API, 브라우저 Geolocation API
- 배포: Vercel (웹) 및 Supabase (백엔드·데이터베이스)

Spring Boot나 별도 Python 서버가 필요한 복잡한 서비스가 아니라면, 초기에는 Next.js와 Supabase를 함께 사용하는 편이 인증·파일 업로드·데이터베이스·배포를 한 흐름으로 관리하기 좋습니다. AI API 키는 반드시 서버에서만 사용하고 브라우저에 노출하지 않습니다.

## 권장 설계

### 1. 사용자 흐름을 먼저 확정하기

기능을 한꺼번에 개발하지 말고 핵심 사용 흐름을 먼저 완성합니다.

```text
주민: 지도 접속 → 매장 선택 → 홍보물 확인 → 퀘스트 참여 → 방문 인증
사장님: 로그인 → 사진·키워드 입력 → AI 홍보물 검토 → 게시
관리자: 매장·홍보물·신고 내역 확인 → 부적절한 콘텐츠 관리
```

첫 번째 목표는 주민이 지도를 보고 매장 정보를 확인하는 흐름과, 사장님이 홍보물을 생성해 게시하는 흐름입니다. 리워드와 TTS는 기본 흐름이 안정된 뒤 추가합니다.

### 2. 화면을 역할별로 나누기

- 주민 화면: 지도, 매장 상세, 오늘의 소식, 퀘스트, 마이페이지
- 사장님 화면: 내 매장, 홍보물 생성, 게시물 관리, 방문·퀘스트 현황
- 관리자 화면: 매장 승인, 신고 처리, 콘텐츠 숨김, 통계

고령 주민도 사용할 수 있도록 핵심 버튼은 크게 만들고, 지도에서 매장 상세 화면으로 이동하는 단계를 최소화합니다. 색상만으로 상태를 구분하지 말고 텍스트와 아이콘을 함께 사용합니다.

### 3. 데이터베이스를 기능보다 먼저 설계하기

Supabase에는 다음 테이블을 기준으로 시작하는 것을 권장합니다.

```text
profiles       사용자 정보와 역할(주민·사장님·관리자)
stores         매장명, 위치, 업종, 운영시간, 접근성 정보
posts          매장 홍보 문구, 이미지, 음성, 게시 상태
quests         퀘스트 조건, 대상 매장, 보상
visits         사용자 방문 인증 기록과 인증 시각
rewards        사용자별 포인트, 쿠폰, 사용 상태
reports        신고 대상, 사유, 처리 상태
```

매장 위치는 위도·경도와 주소를 함께 저장하고, 사용자의 현재 위치와 방문 인증 정보는 꼭 필요한 범위에서만 보관합니다. 주민 개인정보와 사장님 관리 기능은 Supabase Row Level Security(RLS)로 역할별 접근을 제한합니다.

### 4. API 경계를 분명히 하기

프론트엔드가 데이터베이스를 무분별하게 직접 수정하지 않도록 주요 작업은 API 또는 서버 액션으로 감쌉니다.

```text
GET    /api/stores              매장 목록·지도 조회
GET    /api/stores/:id          매장 상세 조회
POST   /api/posts/generate      AI 홍보물 생성
POST   /api/posts               홍보물 게시
GET    /api/quests              진행 가능한 퀘스트 조회
POST   /api/visits/verify      방문 위치 검증 및 기록
POST   /api/reports             콘텐츠 신고
```

AI 생성 요청은 비용과 응답 시간을 고려해 로딩·실패·재시도 상태를 반드시 제공합니다. 생성 결과는 자동 게시하지 않고 사장님이 확인한 뒤 게시하도록 설계합니다.

### 5. 단계별 개발 순서

1. Figma에서 주민·사장님 핵심 화면과 클릭 흐름 작성
2. Next.js 프로젝트, GitHub 저장소, 환경 변수 구성
3. Supabase 인증과 `stores`, `posts` 테이블 구현
4. 지도에서 매장 목록을 조회하고 매장 상세 화면 연결
5. 사장님용 사진 업로드와 AI 홍보 문구 생성 구현
6. 홍보물 검토 후 게시하고 주민 피드에 표시
7. 퀘스트와 GPS 방문 인증, 포인트 적립 추가
8. 접근성 점검, 모바일 테스트, 배포 및 발표용 시나리오 검증

각 단계가 끝날 때마다 실제 휴대폰 화면에서 테스트합니다. 특히 GPS는 실내·저전력 모드·위치 권한 거부 상황을 확인하고, AI가 실패해도 기존 매장 정보와 서비스 이용에는 문제가 없도록 구성합니다.

## 팀
